`OwnedLaunch` retains an ephemeral backend launch reference, launcher PID/creation time, expected executable(s) and exact command identity. A Python virtual-environment redirector's child can match only the backend-known base interpreter and the exact reviewed script arguments, through a validated live ancestry chain. Same titles, unrelated Python scripts, unexpected runtimes, PID reuse, closed or ambiguous windows, and changed attached window identities are rejected. Records expire after 20 minutes and are bounded to 16 per runtime; they are not restored or replayed after restart. Conservative limitations remain for detached launchers, brokered/UWP launches and arbitrary helper-process trees; they do not become accepted merely because a title matches.

Python binds file hashes and fixed arguments to existing launch/script-execution approvals, rechecks denials and files before `Popen(shell=False)`, and returns a launch reference. This intentionally launches trusted user-selected local code with account permissions, not a sandbox. It does not replace Studio generated-code isolation.
