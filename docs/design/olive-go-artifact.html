Browser redesign · design direction and implementation brief

OLIVE GO

A quiet chrome, one bright field, and an empty page that belongs to you. The reference gets this right; OLIVE GO keeps its silhouette and rebuilds every surface in OLIVE's own material — ink ground, blue focus, the green olive as the only mark.

1 · Concept

Quiet chrome, one bright field

Three decisions carry the reference, and they carry OLIVE GO too. The chrome is one band, not two: tabs and toolbar share a colour and the active tab pours into the toolbar, so there is no stacked header. The address field is the only lit object in the chrome — everything else is a muted glyph until you hover it. The new tab page is nearly empty: a mark, a name, a field, then whatever you have pinned, and nothing else claiming space.

What changes is the material. The reference is neutral charcoal with an orange mascot; OLIVE is blue-black ink with a green olive. So OLIVE GO's ground is #0b0f16 not #1c1c1c, its focus and progress are OLIVE blue, and the olive is the one warm thing on the screen — used exactly once per screen as the mark, never as an accent on buttons.

Taken from the reference

  • One-band chrome: tab strip and toolbar in one colour, active tab connected to the toolbar with soft shoulders.
  • A single centred address field, wide, pill-shaped, that is the only lit control.
  • Home · ⟵ ⟶ ⟳ on the left, one menu glyph on the right, nothing else in the bar.
  • New tab: mark + name + field centred in the upper third; favourites as a row of rounded tiles with dashed empties; a small Customize in the bottom-right.
  • Secondary surfaces as a right-hand side panel that slides over the page, never a modal.
  • A one-button "leave no trace" gesture with a calm explanatory popover.

Changed for OLIVE

  • No OS title bar in the browser: OLIVE GO lives inside the OLIVE shell with the navigation pane to its left, so the tab strip is the page's first row.
  • The mark is the OLIVE olive — the icon file already used for the desktop app — never a mascot, never animated on the new tab page.
  • "Search privately" becomes Search or enter address. OLIVE GO does not promise privacy the engine underneath doesn't give; private tabs are where that promise is made, and they say so.
  • The second glyph in the field is Ask OLIVE: send this page or this query to Chat. It replaces the reference's AI shortcut with the one OLIVE already has.
  • "Fire" becomes Clear: new private tab, or clear browsing data — same popover shape, OLIVE's words.
  • No theme colour swatches and wallpapers. OLIVE GO follows OLIVE's theme; Customize controls sections and search engine, not paint.

Errors are OLIVE GO's own page, not Chromium's: the mark small and dimmed, a plain sentence about what happened, what to do, and the raw code in mono for anyone who needs it. The backend already reports did-fail-load with code and description; the page maps the common codes (-105 name not resolved, -106 offline, -118 timed out, -501 insecure) to their sentences and falls through to the description otherwise. 4 · Motion

Alive, not busy

Every animation below moves one property for one reason and finishes inside 240ms. Two easings, no springs: --ease-out: cubic-bezier(.2,.8,.2,1) for things arriving, --ease-in-out: cubic-bezier(.4,0,.2,1) for things travelling. With prefers-reduced-motion every duration is 0 and every offset is 0; opacity still changes so state stays visible.

6 · Implementation brief

How it gets built in OLIVE

The backend stays. desktop/electron/main/browser.ts already does the hard part correctly — one WebContentsView per tab, a persistent session and a throwaway private session, sandboxed pages, downloads that always ask, bookmarks, history, reopen, find, zoom, and a validated action contract in desktop/electron/browser.ts. OLIVE GO is a new renderer on top of it plus a handful of contract additions.

What is replaced

desktop/src/features/Browser.tsx and browser.css are deleted and replaced by a desktop/src/features/go/ folder. The route id stays browser; the registry entry in navigation/features.ts becomes label: 'OLIVE GO', description: 'Browse the web in your own browser.', aliases ['browser','web','tabs','favourites','downloads']. The Home tile and navigation row rename themselves from that one change.

Contract additions

All additive; the existing actions keep their shapes so nothing else in the app changes.

// BrowserTab gains
favicon: string        // data: URI captured from page-favicon-updated, cached per host
progress: number       // 0..1 from did-start-loading / did-stop-loading + a timer ramp; 1 when idle
secure: 'https' | 'http' | 'none'
pinned: boolean

// BrowserRecord (favourites) gains
favicon: string; order: number; pinned: boolean   // order drives new-tab tiles

// New actions
{action:'pin', id, pinned:boolean}
{action:'move', id, index:number}                  // tab reorder
{action:'favourite-reorder', urls:string[]}
{action:'clear-data', history:boolean, cookies:boolean, cache:boolean}
{action:'suggest', text:string}                    // engine suggestions, main-process fetch, only when enabled
{action:'home'}                                    // navigate active tab to about:blank (the new tab page)
{action:'set-search', engine:'google'|'duckduckgo'|'bing'}
{action:'open-external', id}                       // shell.openExternal(active url) after the usual approval

Search engine. navigationURL() currently hard-codes Google. It takes the engine as a parameter; the three templates live in one map in electron/browser.ts. Suggestions go through the main process (net.fetch) so the renderer never talks to the network, and only when Search suggestions is on — the setting's own copy says what it sends.

Rendering over a native view

The page is a native WebContentsView, so React can only draw where the view isn't. The existing layout effect in Browser.tsx is the right mechanism and moves to Go.tsx unchanged in spirit: it measures the page holder, sends {action:'layout', bounds, visible}, and hides the view whenever a dialog, the navigation overlay, an error, or the new tab page is showing. Three refinements:

  • Side panel: visible stays true and bounds.width shrinks by 320 on the same frame the panel starts to animate. The page is visible beside the panel, as in the reference.
  • Suggestions and popovers overlap the top of the page. Because the native view would paint over them, the view's bounds are moved down by the popover's height while it is open (bounds y += 240), and restored on close. This is the one place the page briefly shifts; at 160ms it reads as the panel pushing it.
  • New tab and error pages are React inside the holder; the view is hidden (visible:false) while they show. about:blank is the new tab page.

Data and persistence

  • Favicons: captured in main on page-favicon-updated, fetched through the page's own session, downscaled to 32px PNG data URIs, cached in the existing browser state file keyed by host. Never fetched from the renderer.
  • Favourites = the existing bookmarks list with order, pinned and favicon; the new tab tiles are the first twelve by order. History unchanged (cap 2,000, private never written).
  • Customize choices and the Browser settings category persist through OLIVE's existing settings service, not a second store.
  • Per-tab UI state that matters across restarts — open tabs and their order, pinned — is already restored by the backend; the active tab id is added.

Theming and accessibility

  • .go reads the four new tokens from tokens.css, defined for both themes, so OLIVE GO follows OLIVE's theme and never carries its own switch.
  • Tab strip is role="tablist" with arrow-key movement; the address input is labelled Search or enter address; suggestions are a listbox with aria-activedescendant; the side panel is a labelled region, not a dialog, so the page behind it stays reachable; Escape closes the topmost surface.
  • Shortcuts: Ctrl+T new · Ctrl+W close · Ctrl+Shift+T reopen · Ctrl+Tab / Ctrl+Shift+Tab switch · Ctrl+1…9 · Ctrl+L focus field · Ctrl+D save · Ctrl+H history · Ctrl+J downloads · Ctrl+Shift+N private tab · Ctrl+F find · F5 · Alt+← / Alt+→. Registered on the OLIVE GO route only, so they never shadow Studio's.
  • Contrast: every text colour on every surface above 4.5:1 in both themes; the faint path text is 4.6:1 on the field.

Security, unchanged

Pages stay sandboxed with context isolation and no Node; the renderer still cannot reach the network except through validated IPC; downloads still open the native save dialog and never run; camera, microphone, location and device permissions stay blocked; only http: and https: navigate and credentials in URLs are refused. Open in system browser goes through OLIVE's existing external-open approval. Ask OLIVE keeps the existing quoting: the page's text is handed to Chat as untrusted source material inside the same tags Browser.tsx uses today, never as instructions. Clear browsing data clears the normal session's storage and history only; favourites and the private session are untouched (private clears itself when its last tab closes).
